# ひらがじゃん オンライン

ひらがな牌で「言葉」をそろえる麻雀風ゲーム「ひらがじゃん（プロ版）」を、友だち同士でブラウザから遊べるようにした非公式のオンライン版です。ルールは [docs/rule-book.md](docs/rule-book.md) に基づきます。

- 部屋を作って招待リンクを送るだけで遊べます（ログイン不要。名前を入れるだけ）
- 2〜4人打ち。足りない席は CPU（強さ3段階）で埋められます
- 親・リーチ・一発・ポン・カン・フリテン・流局・本場・供託・ウマオカまで、ルールブックの役と点数計算を実装
- アガリは自己申告で、宣言した語を他の人が確かめます（アナログ盤と同じ流れ）

## 遊び方（オンライン版の操作）

### 部屋に集まる

1. 名前を入れて「部屋を作る」。
2. 上に出る部屋コードをクリックすると招待リンクがコピーされます。友だちに送ってください。
3. ホストがルールを決め、人数が足りなければ「空席をCPUで埋める」を押して「対局開始」。

途中で通信が切れても、同じブラウザで招待リンクを開き直せば自分の席に戻れます。

### 言葉を並べる（このゲームの肝）

本物のひらがじゃんと同じく、**言葉は自分で見つけて並べます**。コンピュータが代わりに言葉を探すことはありません。

| 操作 | やり方 |
| --- | --- |
| 並べ替え | 牌をドラッグ |
| 区切る／つなげる | 牌と牌のすき間をクリック（区切ると隙間が空き、語の下に線が出ます） |
| 語で集める | 手牌の下の入力欄に語を打って Enter（例：`さくら`）。その牌が集まって1つの組になります |
| 打牌 | 牌をクリックして選び、もう一度クリック（設定で1クリック打牌も可）。上に大きくドラッグしても切れます |
| 全部区切る／リセット | 1枚ずつに区切る／五十音順に並べ直す |

手牌の下には区切った組の文字数（例：`2・3・3・3・2 テンパイの形`）が出ます。これは形だけの目安で、言葉として正しいかは教えません。

### 自己申告（標準）：宣言して、みんなで確かめる

アナログ盤と同じく、アガリは自己申告です。ボタンはいつでも押せ、正しいかどうかは宣言したあとに他の人が確かめます。

- **ツモ**：手番ならいつでも「ツモ」を押せます。14牌を「2文字×1＋3文字×4」（七対子ありのルールなら、異なる2文字×7も可）に並べて宣言します。ツモ牌が1枚離れていれば、入れる場所を選べます。
- **理牌タイム**：局の始めに全員で理牌する時間（標準3分、ロビーで なし／1分／5分 も選べます）があります。親は14枚を持った状態で並べられるので天和も狙えます。全員が「理牌完了」を押すか時間になると始まります。
- **ロン・ポン・カン**：誰かが牌を捨てると、5秒（設定で8・10・12秒）だけ全員に「ロン／カン／ポン／スキップ」が出ます。何もなければ次の人へ進みます。
  - ロン：押したあと、ロン牌を自分の語のどこに入れるかを選びます（30秒）。宣言の取り消しはチョンボです。
  - ポン：2枚の組に、カン：3枚以上の組に、捨て牌を入れた語を選びます。辞書にない語でも鳴けます（アガったときに、辞書にない語は投票で確かめます）。
- **確認**：宣言すると手牌が公開されます。辞書（ルーム辞書を含む）にある語は自動で認め、辞書にない語・同種のテーマ・作文だけを投票にかけます（多数決、同数は不可、時間切れは承認）。全部辞書にある語なら投票なしでアガリです。CPUは辞書にない語を認めません。
- **チョンボ（満貫払い）になるとき**：語が認められない、役なし、ロン宣言の取り消し、流局時のノーテンリーチ。形は宣言した手から自動で確かめます。
- **フリテン**（アガリ牌と同じ文字を自分で捨てている／同じ文字を見逃した直後／リーチ後に同じ文字を見逃した）の文字が捨てられたときは、鳴きのボタンの横に「フリテン：…」と警告が出て、ロンは押せません（うっかりチョンボを防ぐため）。ツモはできます。
- **リーチ**：テンパイかどうかは自己申告です。リーチ後はツモ切りしかできませんが、並べ替え（読み替え）は自由です。ひらめき次第で待ちを変えたり広げたりできます（左下の「ツモ切り」で自動にできます）。
- **観戦**：対局中の部屋に入ると観戦になります。上の「観戦中」の並びか、左右の矢印（←→キーでも可）で参加者を選ぶと、その人の席から見た卓と手牌（理牌や並べ替えもその場で）が見られます。
- **供養**：局が終わったとき、結果画面の「供養する」から、自分の手牌に好きな牌を2枚まで足した完成形をみんなに見せられます（点数には関係しません）。入力時の空白は、結果画面やチャットでは詰めて1列に表示します（作文のアガリと同じ見せ方）。⚙設定の「供養モード」でいつでもオフにでき、オフにすると供養のボタンも他の人の供養も出なくなります。
- **作文**：鳴きなしで、14牌を区切らずに1つの文章として並べると「作文」ボタンが出ます（投票で判定、3翻）。
  - 作文待ちでリーチするときは、13枚を区切らずに並べ、切る牌だけ離してリーチします。リーチ中のツモ・ロンでは、アガリ牌を文章のどこに入れるかを選んで宣言します。
  - 流局時、区切らずに並べてリーチしている人は「あと1牌で文章になるか」を他の人が投票で確かめます。否決ならノーテンリーチ（チョンボ）です。

### 辞書と投票

- 判定には JMdict から作った約20万語（常用語のみ＝約2万語も選べます）を使います。
- 辞書にない語は「マイ単語」に登録しておくと、ポン・カンに使えます（他の人には見えません。アガリのときは投票で判定）。投票で承認された語はルーム辞書に入り、以後は全員が使えます。
- 同種・純同種を狙うときは「同種」パネルでテーマを宣言しておきます。アガったときに投票で判定します。
- ロビーでは語を調べたり、ルーム辞書に先に語を入れたりできます。

### そのほか

- 右上の ⚙ から効果音・発声（ポン・ロンなどの読み上げ）・1クリック打牌を切り替えられます。ホストは対局を中断できます。
- PC向けの画面です。

## オンライン版での取り決め

ルールブックの【補完】部分に加えて、オンライン化のために次のように決めています。

- アガリ・テンパイ・鳴きは、プレイヤーが並べた組で判定します（牌を自由に並べ替えられるため、コンピュータが言葉を探すとほぼ全ての配牌がアガリ形になってしまう）。
- 「次の人がツモ牌に触れるまで」は、打牌後の受付時間（標準5秒）として扱います。
- 流局時のテンパイは並べた形を辞書で確かめます。並べていない手はノーテンです（作文待ちのリーチだけは投票で確かめます）。
- カンドラはルールブックの「カン1つにつき（文字数−3）翻」から、カン1つにつき1翻までにしています。長い語のカン1つで跳満に届き、カンした本人だけが確実に得をするためです（長い語は補充で多く引けるのが得）。
- 作文はルールブックの4翻から3翻に下げています。待ちが広く投票も通りやすいので、気心の知れた仲間内だと作文ばかり狙われてしまうためです。
- リーチ後も手牌の並べ替え（読み替え）ができます。麻雀でもリーチで縛られるのは手牌の牌で、読み方は自由なためです。牌を変えられないので、リーチの重みは残ります。
- リーチ後の暗カンはできません。作文はロンでもアガれます。
- フリテンは「アガリ牌と同じ文字」だけで判定します。ルールブックは「待ちのどれかを捨てていたら」ですが、辞書の語が多く、1文字の単騎だと待ちが40種類にもなって、思いもしない語でフリテンになるためです。
- 基本の牌（濁音などの追加なし）では、清文・特文・純特文・特殊文字ドラはありません。特殊文字が「ー」1枚だけなので、清文はほぼ必ず付き、特文系は作れないためです（シミュレーションでは清文がアガリの88%に付いていました）。
- 純行はルールブックの4翻（門前5翻）から6翻（門前8翻）に上げています。シミュレーションでは、並べ方を全部知っていても純行を作れる手がアガリの0.5%ほどしかなく、清一色（6翻）並みに珍しいためです。
- 七対子はルール設定で選べ、既定は「なし」です。2文字の語は作りやすく、人どうしでも成立しすぎるためです。
- ポン・カンは辞書にない語でもできます（ルールブックの「誤った鳴き」は使いません）。語はアガったときに、ほかの語と同じく投票で確かめます。
- 回文は2文字以上の語で数えます。純行は五音と重ねません。一発は暗カンでも消えます。
- 否決時の扱い（チョンボ／取り消しのみ）はロビーで変えられます。

## 開発

Node.js 20 以上が必要です。

```bash
npm install
```

```bash
npm run dev
```

ブラウザで http://localhost:5173 を開きます（ゲームサーバーは 3001 番、Vite がそこへ中継します）。同じPCで複数人を試すときは、URL に `&as=2` のように付けると別の人として入れます。

| コマンド | 内容 |
| --- | --- |
| `npm test` | ルール・役・進行のテスト（vitest） |
| `npm run typecheck` | 型チェック |
| `npm run sim -- 4 normal tonpuu 4` | CPU同士の対局シミュレーション（対局数・強さ・長さ・人数） |
| `npm run build` → `npm start` | 本番ビルドと起動（`PORT` 環境変数、既定 3001） |

### 修正とリリースの流れ

- `develop`：ふだんの作業用。何度プッシュしても公開中のサーバーには影響しません。
- `main`：公開用。Render はこのブランチを自動でデプロイします。デプロイするとサーバーが入れ替わり、進行中の対局は消えます。
- リリースは、誰も遊んでいないときに `develop` を `main` にマージしてプッシュします。
- 遊んでいる人がいるかは `/api/status` で確かめられます（`activeGames` が 0、`safeToRelease` が true なら安全）。対局と接続の数だけを返し、名前などは出しません。

### 役のバランスの検証

対局でのアガリは、サーバーを起動したフォルダの `logs/agari.jsonl` に1行ずつ記録されます（`LOG_DIR` で保存先を変更可）。

- **ダウンロード**：`/api/agari-log` から取れます。`LOG_KEY` を設定したときは `/api/agari-log?key=…` が必要で、未設定ならサーバーと同じPCからだけ取れます。
- **注意**：Render の無料プランなどはファイルが再起動で消えるので、こまめにダウンロードしてください。
- **見逃し分析**：記録された14牌を辞書で並べ直し、作れた役と実際に付けた役を比べます。

```bash
npx tsx scripts/analyze-agari.ts logs/agari.jsonl --dict common
```

- `--dict common|full`：並べ直しに使う辞書（常用語／全語）。人が思いつける語に近いのは `common` です。
- `--who human|bot|all`：誰のアガリを見るか（既定は人のみ）。
- **出力**：役ごとに、付いた率・作れた率・見つけた率（付いた÷作れた）と、取りこぼしの大きかったアガリを出します。
- **シミュレーションを分析する**：`RECORD=sim.jsonl npm run sim -- 30 normal tonpuu 4` でCPU同士のアガリを同じ形式で書き出し、`--who bot` で分析します。CPUは役を狙わないので、付いた率は「偶然つく率（下限）」、作れた率は「並べ方を全部知っていたら作れた率（上限）」の目安になります。

### 構成

```
src/shared   ルールの中身（牌・辞書の索引・並びの判定・役と点数・通信の型）
src/server   Socket.IO サーバー（部屋・対局の進行・CPU）
src/client   React の画面（タイトル・ロビー・対局・結果）
data/        辞書（words.txt.gz）
scripts/     辞書の作成・シミュレーション
tests/       テスト
```

対局の判定はすべてサーバーで行い、各プレイヤーには自分の手牌だけが送られます。

## 友だちと遊ぶための公開

部屋の情報はサーバーのメモリにだけあるので、1台の Node.js サーバーで動かします。

**Render（無料枠）の例**：このリポジトリを Render の「New → Blueprint」で選ぶと `render.yaml` の設定で公開されます。無料枠は15分使わないと休止し、次のアクセスで起動に30秒ほどかかります（休止すると部屋は消えます）。

**Docker**：`docker build -t hiragajong . && docker run -p 3000:3000 hiragajong`

**自分のPCで一時的に**：`npm run build && npm start` のあと、Cloudflare Tunnel や ngrok で 3001 番を公開すれば、URL を送るだけで遊べます。

## 辞書データ

`data/words.txt.gz` は [JMdict](https://www.edrdg.org/jmdict/j_jmdict.html)（© EDRDG, CC BY-SA 4.0）を [jmdict-simplified](https://github.com/scriptin/jmdict-simplified) 経由で読み、ひらがな（カタカナはひらがなに変換）の2〜12文字の語を取り出したものです。作り直すときは `node scripts/build-dict.cjs jmdict-eng-x.y.z.json` を実行します。
